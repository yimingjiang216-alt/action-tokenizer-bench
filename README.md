# 动作分词器对照实验 — 轨迹怎么进词表

一句话：在同一条**带米制真值的真实轨迹**上，把「连续动作 / 单层大码本 / 残差量化 RVQ / RT-2·OpenVLA 式逐维均匀分档」四种动作表示法的误差、token 成本和尾部风险摆在同一张表里，用来验证 LightNav-0 公开的那一格选择（三级 RVQ 把 10 个 SE(2) 路点压成 3 个 token）到底赢在哪、代价是什么。

只有 numpy，CPU 上 7 个配置约 5 分钟。

```bash
pip install -r requirements.txt
python run.py --selftest                                        # 结构自检（不需要数据）
python run.py                                                   # 合成分布（可控对照）
python run.py --gt data/rgbd_dataset_freiburg1_xyz/groundtruth.txt \
              --mode se2 --step 10 --stride 1 --out results/tum_se2_s10.json
python report.py --dir results --out RESULTS.md                 # 所有表由此生成
GT=data/rgbd_dataset_freiburg1_xyz/groundtruth.txt bash run_all.sh   # 一次跑完七张表
```

真实数据：TUM RGB-D 数据集 `freiburg1/xyz` 的 `groundtruth.txt`（3000 帧米制位姿，100 Hz）。数据不随本仓库提供，需从官方页面下载：<https://cvg.cit.tum.de/data/datasets/rgbd-dataset/download>。本仓库里所有数字都由 `results/*.json` 生成，这些 json 一并提交——**没有 TUM 数据也能直接 `python report.py` 复算全部表格**；但换一份轨迹，数字就不是这些了。

## 一、结论先说

1. **单层码本的精度被样本数卡死，不是被比特数卡死。** 真实轨迹 1 秒窗口上，K 从 256 → 4096（8 → 12 bits），留出集 ADE 只有 1.90 → 1.87 cm（纹丝不动），拟合集却从 0.46 → **0.00** cm。原因很直白：拟合集只有 2031 条窗口，比 4096 个码字还少，量化器退化成查表。合成对照组有 14000 条拟合窗口（远大于 4096），同一现象小一号但方向一致：K=4096 拟合 4.92 → 留出 7.76 cm，而每级只有 256 码字的 RVQ 三级从 2.70 → 3.11 cm。**所以「单层 K=4096 只要 12 bits」这种账要打折看：码本容量接近或超过语料量之后，比特数是虚的。** 这也解释了 FAST 为什么要攒约 100 万条真实轨迹才敢喂一个大码本。
2. **同样的精度，RVQ 用 10 倍少的 token。** 对齐到 ~1.2 cm 这一档（真实轨迹 1 秒窗口）：RVQ **3 个 token / 24 bits**；OpenVLA 式逐维分档要 **32 档 × 30 维 = 30 个 token / 150 bits**。七个配置（两种表示 × 两种时长 × 三种合成）里 token 差永远是 3 vs 30，bits 差在 5–8.75 倍之间（见第五节的跨配置表）。**分词器之争本质是自回归序列长度之争**：token 数决定解码步数、推理延迟和训练词元预算，误差只是表象。
3. **但均匀分档给的是有界误差，学习型码本不给。** 逐维 32 档的每轴步长是事先算得出的：平面 x 范围 0.70 m / 32 = 2.19 cm，实测 max 1.8 cm、p95 1.55 cm。RVQ 3 token 的 max 是 **7.7 cm**，是它自己 p95（3.57 cm）的 2.2 倍，而且尾部不单调——RVQ 2 token 的 max（8.4 cm）比 RVQ 3 token 的还大。k-means 优化的是平均平方误差，它把码字花在常见动作上，稀有动作就吃大亏。**这是产品口径问题，不是模型好坏问题：要么写「ADE ≤ X 且 max ≤ Y」，要么给学习型分词器加显式的截断/兜底策略。** 反过来，均匀分档的越界失败是**可检测**的：留出样本一旦超出标定范围就会被裁到边界，编码时看得见他；RVQ 的大残差只是安静地错。
4. **动作的编码口径比码本设计更能左右结论，而且会虚增单层码本的精度。** 合成臂最早把朝向编成**全局绝对航向**；改成和真实臂一致的**相对窗口起点**（第 0 个路点恒为 (0,0,0)）之后，同一套算法、同一个随机种子、同一批平面位移下：单层 K=256 留出 ADE 从 15.18 涨到 **18.47 cm**、K=4096 从 6.49 涨到 7.76 cm，而 RVQ 3 token 反而从 3.40 降到 **3.11 cm**。绝对航向是免费信息——策略本来就以当前朝向为条件做预测，再把它塞进动作向量等于让码本顺手记住全局方向。同一个口径问题对逐维分档更致命：8 档的朝向 MAE 从 **35.6°**（绝对）降到 **10.2°**（相对），因为那个粗糙网格要同时覆盖 ±π 弧度和 3 米位移。仓库里保留了 `--heading absolute` 这个对照组（`results/synth_abs_head.json`），所以这条是可复算的。**读别人的分词器结果，第一个要问的是「你的路点是绝对的还是相对的」，而不是「你用了几个码字」。**
5. **差分（delta）编码在位移上赚，在朝向上可能亏。** 真实 1 秒窗口：256 档 ADE 0.12 → 0.03 cm、朝向 0.03 → 0.02°，两项都改善；合成分布：ADE 0.90 → 0.20 cm，但朝向 MAE 从 0.32° 涨到 **1.22°**。原因是差分把解码变成累加（`cumsum`），末尾路点的误差是十步量化误差之和（自检里检查的上界就是 `K × 档宽`）。**同一档数、同一 token 成本下，收益要分维度算**——这正是机械臂动作（位移几米、夹爪 0/1）这种混合量纲最容易踩的地方。

## 二、设定

| 项 | 取值 | 依据 |
|---|---|---|
| 轨迹表示 | 10 个路点，每点 3 维。`--mode se2` = (x, y, yaw)；`--mode xyz` = 完整三维平移 | 对齐 LightNav-0 的「10 个 SE(2) 路点 → 3 token」 |
| 路点编码 | **全部相对每个窗口的第 0 个路点**：平移减 w[0]，朝向减 w[0] 并 wrap 到 ±π，所以第 0 个路点恒等于 (0,0,0)；真实臂与合成臂同一口径 | 策略是在当前状态上做条件预测，绝对量属于重复编码（见结论 4） |
| 真实数据 | TUM `freiburg1/xyz` groundtruth.txt，3000 帧 @ 100 Hz | 米制、自带位姿真值，不需要重建 |
| 窗口 | `--step` = 路点间隔帧数（10 → 1 秒窗口 / 10 Hz 路点；2 → 0.2 s / 50 Hz；1 → 0.1 s / 100 Hz）；`--stride` = 窗口起点间隔（固定 1） | 一份数据同时覆盖导航频率和操纵频率两档 |
| RVQ | 每级码本 256，k-means++ 逐级量化残差，贪心拟合；一次拟合 4 级，解码任意前缀 | 对齐其「256 粗码本 + 两级残差」 |
| 单层 | K = 256 / 1024 / 4096，整条轨迹当一个向量、1 个 token | 对齐其对照档「单层 K=4096 分词器」 |
| 逐维分档 | 8–256 档，两种范围口径：`coord`（每个坐标共享，RT-2/OpenVLA 原样）与 `waypoint`（每个路点独立，对基线更有利的变体）；另加 delta 两组 | 两种都报，避免把基线写得比实际更弱 |
| 指标 | ADE / p95 / max（路点位移误差）、yaw MAE、前 1–4 点 vs 后 6–10 点分段、token 数与 bits | 平均达标不等于尾部可用 |
| 随机性 | `SEED=0`，k-means++ 初始化按级 `SEED+level`，同机同版本 numpy 可复现 | — |

## 三、真实轨迹怎么变成 SE(2)

TUM 的 `freiburg1/xyz` 是**手持 Kinect 在空中比划 XYZ 三个方向**，不是地面机器人轨迹：三轴平移方差近乎各向同性（`meta.pca_var_ratio` = 0.451 / 0.300 / 0.249），没有现成的「地面」。所以不能假设世界系 x/y 就是水平面，`run.py` 里按物理量标定：

- **重力方向** = 全体帧相机 y 轴（图像里「向下」）的均值方向。该序列手持姿态稳定，相机下轴偏离这个均值最多 15.9°（`meta.cam_tilt_var_deg`），说明估计可用。
- **水平面** = 与该方向正交的平面；**朝向** = 相机光轴（z 轴）投影到该平面后的 `atan2`。
- **丢掉的分量**：沿重力方向的位移（本序列标准差 0.094 m）以及 roll/pitch——这是 SE(2) 接口本身的取舍，不是我的近似。
- 因为投影是有损的，我额外跑了 `--mode xyz`（不丢垂直分量、也不编朝向）作为对照，两栏都在 `RESULTS.md`。
- **朝向通道几乎没有信号**：全序列 heading 只有 24.5° 的极差、标准差 4.9°。所以本实验里 yaw MAE 那几列不能当作「朝向能力」的证据，只能当副作用看。真要考朝向，得换有转身动作的序列。
- 四元数转旋转矩阵做了数值校验并写进 meta：`max |RRᵀ − I|` = 1.55e-15，`max |det R − 1|` = 1.78e-15。

## 四、评测协议

- **时间前后切分**：前 70% 的窗口拟合码本 / 确定分档范围，后 30% 打分；两者之间**再丢掉一整段窗口**，因为滑窗重叠会让边界窗口和拟合集共用帧。丢弃量是 `guard = (K_POINTS−1)×step/stride + 1`：1 秒窗口（step=10, stride=1）是 **91 个起点 = 9.1 秒**，step=2 是 19 个，step=1 是 10 个。拟合集与留出集的 ADE 在表里分列（最后一列 `fit-set ADE`）。
- **为什么必须切**：单层 K=4096 在 2031 条窗口上会把码字用光，不切分就会报出 0.00 cm 这种毫无意义的数字。结论 1 完全来自这个协议。
- **合成分布是对照组，用来证明差距不是切分造出来的**：合成窗口是 i.i.d. 的，不依赖数据量的逐维分档在两种切分下几乎重合（8 档 ADE 27.01 vs 26.98 cm），而学习型码本照样变（K=4096：拟合 4.92 vs 留出 7.76 cm）。所以真实数据上的拟合/留出差是 k-means 的性质 + 样本量不够，不是「后段时间分布前移」这个协议副产品。
- **真值噪声地板**：用 5 点局部二次拟合估的等效白色噪声约 **0.2 mm**（三轴合成，`meta.gt_noise_equiv_mm`），单帧位移中位数在世界系是 3.3 mm（0.331 m/s @100 Hz），投到水平面是 2.2 mm。也就是说 100 Hz 档（`xyz step=1`）没有被噪声淹没，那一档的比较是可读的；但任何低于 0.2 mm 的精度都不该算分词器的功劳。
- 所有 token / bits 记账都是**每条轨迹（10 个路点）一次动作输出**的成本。

## 六、能说什么 / 不能说什么

**能说的**

- 趋势复现：单层码本打不过同级容量的 RVQ；而且任意非空前缀本身就是一台可用的分词器。贪心拟合使 `RVQ 1 token` 与 `single-level K=256` 在**每个配置里数字完全相同**（1.90 / 1.90、0.33 / 0.33、18.47 / 18.47……）——这条恒等式在七个配置上成立，本身就是实现正确的证据。
- 真实米制轨迹（1 秒窗口）上 RVQ 逐级码字的平均位移是 **0.120 / 0.006 / 0.002 / 0.001 m**：第一级定粗向，第二级掉 20 倍，之后每级约 3 倍。把视距拉到合成导航分布（窗口位移中位数 1.9 m）上，阶梯变成 **0.982 / 0.206 / 0.056 / 0.027 m**——第一级正好落在米级。这是「粗到细」的实测形状。
- token 数是硬约束（结论 2），尾部风险必须单独验收（结论 3），编码口径要先问清（结论 4），delta 收益要分维度算（结论 5）。

**不能说的**

1. **不能报「追平了他们的 0.72 cm」。** 他们的 10 个路点覆盖的是米级导航视距，我的一秒窗口只有 0.13 m；把相对误差摊开是真实数据 ≈ 窗口位移的 2.7%–9.2%、合成 ≈ 1.4%–1.8%，量级和口径都不同，只能说方向一致。
2. **没有复现 FAST 的前提。** 「标准逐维离散化在高频控制上失败」在我这里没出现：100 Hz 档逐维 8 档也只有 0.37 cm，因为手持相机轨迹本身就是低频、维度耦合弱的信号。要检验它需要真实的机械臂动作流（π0.5 在 LIBERO 上是 20 Hz、7 维动作，含夹爪突变），那才是能压垮均匀分档的数据。
3. **单层大码本「多少码字能追平 RVQ」我给不出答案**：码字上限被样本数卡着，扫到 24 bits 以上只会得到「全部记住」的假数字（拟合集 0.00 cm）。这条只能作为方法学结论报出。
4. **朝向是一个被 wrap 到 ±π 的欧氏标量**，所以 ±π 处有不连续。合成臂的大漂移窗口正好跨过它（`heading_ptp_deg` = 360），真实臂没有（24.5°）。要彻底避免应该编码 (sin, cos) 或只用小窗口——这一条我没做，所以合成臂的 yaw 列比真实臂的更保守。
5. **没有障碍物、没有碰撞、没有闭环策略。** 这是分词器实验，不是导航成功率实验：任何 SR / SPL 都不能从这里推。真实场景里 7.7 cm 的 max 误差在某张地图上就等于撞墙。
6. **一条轨迹不构成统计。** 全部真实数据来自同一个 30 秒序列，窗口之间高度相关（虽然窗口起点不同）。换成十个场景就能给出置信区间——这也正是 LightNav-0 自己强调「环境多样性是唯一持续回报的轴」的原因。

## 七、和亮源公开口径的对应关系

| 他们的说法（公开报告） | 本仓库的验证状态 |

| 三级码本把 10 个 SE(2) 路点编成 3 个 token | 结构复现：10 路点 → 3 token 的接口跑得通，且第 1 个 token 单独解码就是可执行的粗轨迹 |
| 0.72 cm（RVQ）vs 2.48 cm（单层 K=4096） | **方向复现，绝对值不可比**：这里是留出集 1.22 cm（RVQ 3 tok）vs 1.87 cm（单层 12 bits）。他们的单层数字若未做 held-out 评测，按结论 1 要打折看；但我的窗口只有 0.13 m 位移，不能直接对表 |
| 256 粗码本 + 两级残差 ≈ 0.9 m / 7 cm / 4 cm 分辨率阶梯 | **只有第一级对上**：合成长视距（1.9 m）下我的阶梯是 0.982 / 0.206 / 0.056 m，第一级确实在米级，第二三级比他们报的粗一个量级。口径注意：我取的是「每个路点上码字位移的均值」，与他们「分辨率」的定义不完全一致，只比形状和第一级量级 |
| RVQ 让动作序列更短 | **定量支持**：同精度下 token 少 10 倍（3 vs 30），bits 少 5–8.75 倍（24 vs 120–210） |

## 八、下一步（明确缺的那块数据）

把 `PER_POINT` 从 3 改成 7、加一个读 (T, 7) 动作数组的载入器，就能把同一套对照搬到机械臂动作上：π0.5 在 LIBERO 的 20 Hz 输出、8 维状态 + 7 维动作，正好是「高频 + 夹爪突变 + 各维尺度悬殊」的组合，也是 FAST 论断真正的靶子，同时能检验结论 5 在真实操纵数据上站不站得住。这一步需要先把 rollout 时的逐步动作存盘（现在只留了成功率），我没有这份数据，所以不猜结论。
