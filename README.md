# 轨迹动作分词器对照实验

把一段动作块（10 个路点）用四种方式编码成离散 token，再解码回来，比较三件事：解码误差、每条动作的 token 数、误差的尾部。

| 方式 | 每组 token 数 | 说明 |
|---|---|---|
| 不分词（连续回归） | 0 | 误差恒为 0，参照用 |
| 单层码本 | 1 | 整组 30 维当一个向量做一次 k-means，K = 256 / 1024 / 4096 |
| 残差量化 RVQ | 1–4 | 每级 256 码字，k-means++ 逐级量化残差，贪心拟合，任意前缀可解码 |
| 逐维均匀分档 | 30 | 每个维度独立切 N 档，N = 8–256；两种范围口径（`coord` 按坐标全局范围，`waypoint` 按每个路点）；另有编码路点间差分的两组 |

数据两条来源：TUM RGB-D `freiburg1/xyz` 的米制位姿（真实），和一个由三个参数生成的平滑 SE(2) 合成分布（可控对照）。共七个配置。只依赖 numpy，单核 CPU 上全部跑完约 2 分钟；`results/*.json` 已提交，重跑逐字节可复现。

## 运行

```bash
pip install -r requirements.txt
python run.py --selftest                                      # 结构自检，不需要数据
python run.py                                                 # 合成分布
GT=data/rgbd_dataset_freiburg1_xyz/groundtruth.txt bash run_all.sh   # 七个配置 + 重新生成 RESULTS.md
```

真实数据从 TUM 官网下载（<https://cvg.cit.tum.de/data/datasets/rgbd-dataset/download>），不随仓库提供。所有表格由 `report.py` 从已提交的 `results/*.json` 生成，没有这份数据也能 `python report.py --dir results --out RESULTS.md` 复算全部数字；换一条轨迹，数字就不是这些。

## 设定

| 项 | 取值 | 说明 |
|---|---|---|
| 轨迹表示 | 10 个路点，每点 3 维。`--mode se2` = (x, y, yaw)；`--mode xyz` = 完整三维平移 | se2 丢垂直分量与 roll/pitch；xyz 不编码朝向 |
| 路点编码 | 全部相对窗口第 0 个路点：平移减 w[0]，朝向减 w[0] 并 wrap 到 ±π，第 0 点恒为 (0,0,0)；真实臂与合成臂同一口径 | 见观察 4 |

| 窗口 | `--step` = 路点间隔帧数（10 → 1 秒窗口 / 10 Hz 路点；2 → 0.2 s / 50 Hz；1 → 0.1 s / 100 Hz）；`--stride` = 窗口起点间隔，固定 1 | 一份数据覆盖不同控制频率 |

| 指标 | ADE / p95 / max（路点位移误差）、yaw MAE、前 1–4 点与后 6–10 点分段、token 数与 bits | 平均与尾部分开 |

## 真实位姿怎么变成 SE(2)

`freiburg1/xyz` 是手持 Kinect 在空中比划 XYZ 三个方向，不是地面机器人轨迹：三轴平移方差近乎各向同性（`meta.pca_var_ratio` = 0.451 / 0.300 / 0.249），没有现成的地面，所以不能假设世界系 x/y 就是水平面。`run.py` 按可观测量标定：

- 重力方向取全体帧相机 y 轴（图像里「向下」）的均值方向。该序列手持姿态稳定，相机下轴偏离均值最多 15.9°（`meta.cam_tilt_var_deg`）。
- 水平面与该方向正交；朝向取相机光轴（z 轴）投影到该平面后的 `atan2`。
- 丢掉的分量：沿重力方向的位移（本序列标准差 0.094 m）以及 roll / pitch。这是 SE(2) 接口本身的取舍。因为投影有损，另外跑了 `--mode xyz`（不丢垂直分量、不编朝向）作为对照。
- 本序列朝向通道几乎没有信号：heading 全序列极差 24.5°、标准差 4.9°。这里的 yaw MAE 各列不能当作朝向能力的证据，只能当副作用看。
- 四元数转旋转矩阵有数值校验并写进 meta：`max |RRᵀ − I|` = 1.55e-15，`max |det R − 1|` = 1.78e-15。

## 评测协议

- 时间前后切分：前 70% 窗口拟合码本与确定分档范围，后 30% 打分，中间再丢掉一整段窗口，因为滑窗重叠会让边界窗口和拟合集共用帧。丢弃量为 `guard = (K_POINTS−1)×step/stride + 1`：step=10 是 91 个起点（9.1 秒），step=2 是 19 个，step=1 是 10 个。拟合集与留出集在表里分列。
- 这一切分是必需的：单层 K=4096 在 2031 条窗口上会把码字用光，不切分会报出 0.00 cm。观察 1 完全来自这个协议。
- 合成臂用来确认差距不是切分造出来的：合成窗口是 i.i.d. 的，不依赖数据量的逐维分档在两种切分下几乎重合（8 档 ADE 27.01 与 26.98 cm），学习型码本照样变（K=4096：拟合 4.92、留出 7.76 cm）。所以真实数据上的拟合/留出差来自 k-means 的性质加样本量，不是协议副产品。
- 真值噪声地板：5 点局部二次拟合估的等效白色噪声约 0.2 mm（`meta.gt_noise_equiv_mm`）。单帧位移中位数在世界系 3.3 mm、投到水平面 2.2 mm，所以 100 Hz 档没有被噪声淹没，那一档的比较可读；但低于 0.2 mm 的精度不该算分词器的差别。
- 所有 token / bits 记账都是每条轨迹（10 个路点）一次动作输出的成本。

## 观察

1. 单层码本的留出误差不随 K 下降。真实 1 秒窗口上 K=256 / 1024 / 4096 的留出 ADE 是 1.90 / 1.88 / 1.87 cm，拟合集却是 0.46 / 0.11 / 0.00 cm。拟合集只有 2031 条窗口，少于 4096 个码字，量化器退化成最近邻查表。合成臂有 14000 条拟合窗口（大于 4096），同一现象小一号但方向一致：K=4096 拟合 4.92 / 留出 7.76 cm，每级 256 码字的 RVQ 三级是 2.70 / 3.11 cm。所以「单层 K=4096 只要 12 bits」这种账要打折：码本容量接近或超过语料量之后，名义比特数不代表实际学到的东西。作为量级参照，FAST 用约 100 万条真实轨迹训练动作分词器（arXiv 2501.09747），比这里的样本量高两个数量级。
2. 同精度下 RVQ 的 token 数少一个数量级。对齐到约 1.2 cm 这一档（真实 1 秒窗口）：RVQ 是 3 个 token / 24 bits；逐维分档要 32 档 × 30 维 = 30 个 token / 150 bits。七个配置里 token 差都是 3 对 30，bits 差 5–8.75 倍。token 数决定解码步数、推理延迟和训练词元预算，这三项跟码本设计无关，是表示法的直接后果。
3. 均匀分档的误差有可预先算出的上界，学习型码本没有。逐维 32 档的每轴步长：平面 x 范围 0.70 m / 32 = 2.19 cm，实测 max 1.8 cm、p95 1.55 cm。RVQ 3 token 的 max 是 7.7 cm，为自身 p95（3.57 cm）的 2.2 倍，而且尾部不单调——RVQ 2 token 的 max（8.4 cm）比 RVQ 3 token 的还大。k-means 优化平均平方误差，码字倾向常见动作，稀有动作误差大。两类失败在工程上不一样：逐维分档遇到越界样本会把它裁到边界，编码阶段看得见；RVQ 的大残差没有这种信号。要约束尾部，要么在验收里写 max / p95，要么给学习型分词器加显式截断或兜底。
4. 路点是绝对编码还是相对编码，对结论的影响大于码本设计。合成臂最初把朝向编成全局绝对航向，改成与真实臂一致的相对窗口起点后，同一套算法、同一个随机种子、同一批平面位移：单层 K=256 的留出 ADE 从 15.18 涨到 18.47 cm，K=4096 从 6.49 涨到 7.76 cm，而 RVQ 3 token 反而从 3.40 降到 3.11 cm；逐维 8 档的朝向 MAE 从 35.55° 降到 10.19°。绝对航向对以当前朝向为条件的策略是重复信息，等于让码本顺手记住全局方向；粗糙的均匀网格则要被 ±π 弧度和米级位移同时占用。`--heading absolute` 与它的 `results/synth_abs_head.json` 留在仓库里，这个差可以当场复算。
5. 差分（delta）编码在位移上减小误差，在朝向上不一定。真实 1 秒窗口：256 档 ADE 0.12 → 0.03 cm、朝向 0.03 → 0.02°，两项都改善。合成分布：ADE 0.90 → 0.20 cm，但朝向 MAE 从 0.32° 涨到 1.22°。差分把解码变成累加，末尾路点的误差是十步量化误差之和，上界 `K × 档宽`（自检检查这一项）。量纲混合的动作（位移米级、夹爪二值）上这两种效应要分开算。

## 局限

- 只测分词器的重建误差。没有闭环策略、没有障碍物与碰撞模型，任何任务成功率类指标都不能从这里推。
- 真实数据只有一条 30 秒序列，窗口之间高度相关，没有置信区间。十个场景才能给区间。
- 这里的窗口位移中位数从 0.030 m（0.1 秒）到 0.132 m（1 秒），是手持相机的短窗口。不能与更长视距的导航动作块比误差绝对值，只能比方向。
- 没有复现「高频控制上逐维离散化会失败」这个预期：100 Hz 档逐维 8 档也只有 0.37 cm，因为外部动捕位姿本身是低频、维度耦合弱的信号。检验它需要真实机械臂关节指令流（例如 20 Hz、7 维、含夹爪突变的操作动作），这里没有。
- 朝向被 wrap 到 ±π 当作欧氏标量，在 ±π 处不连续。合成臂的大漂移窗口正好跨过它（`heading_ptp_deg` = 360），真实臂不会（24.5°）。编码 (sin, cos) 可以避开，这里没做，所以合成臂的 yaw 列比真实臂更保守。
- 「单层大码本用多少码字能追平 RVQ」无法回答：码字上限被样本数卡着，扫到 24 bits 以上只会得到拟合集 0.00 cm 这种假数字。

## 复现与扩展

- `run_all.sh` 串行跑出七个配置，`report.py` 只读 json；`RESULTS.md` 可以字节级重生成（`report.py` 显式写 LF 换行）。README 里两张表取自 `RESULTS.md`。
- 本仓库提交版是在 numpy 1.26.4、单核 CPU、`SEED=0` 下跑出来的；七个配置重跑后生成的 json 与提交版逐字节一致（本机实测总耗时 2 分 12 秒）。
- `run.py --selftest` 检查三件结构性质，不需要数据：RVQ 前缀误差单调下降；`RVQ 1 token` 与 `single-level K=256` 数值完全相同（贪心拟合使两者恒等，这条在七个配置上都成立）；均匀分档误差落在半档内、差分重构误差有界。
- RVQ 逐级码字的平均位移，真实 1 秒窗口是 0.120 / 0.006 / 0.002 / 0.001 m；合成导航分布（窗口位移中位数 1.9 m）是 0.982 / 0.206 / 0.056 / 0.027 m，第一级落在米级。这是粗到细的实际形状。
- 扩展到操作动作：把 `PER_POINT` 从 3 改成 7，加一个读 (T, 7) 动作数组的载入器，同一套对照就能搬到机械臂动作上，同时检验观察 5。需要先把 rollout 的逐步动作存盘，现在只有成功率。
